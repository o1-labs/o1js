# Mesa vendored layout — provenance & maintenance

These files let `mina-signer` produce/verify the **Mesa** zkApp transaction
format alongside the current one (era `'next'`, the format of the network after
the Mesa hard fork). They are frozen snapshots — do not "improve", reformat, or
regenerate them casually.

## Source

- o1js commit: **`bb34e65e7`** (o1js `main` before the post-Mesa layout;
  published signer = `mina-signer@4.1.0`).
- Golden test vectors validating this code: generated by the real
  `mina-signer@4.1.0` and stored at `../test-vectors/mesa.ts`. Their provenance
  is reproducible via `../test-vectors/verify-mesa-vectors.mjs` (re-signs every
  vector with `@4.1.0` and asserts a match).

## The Mesa ↔ next delta

In the zkApp command layout, the only difference is the `setVerificationKey`
permission: Mesa gives it as `{ auth, txnVersion }`, the next format as a bare
`AuthRequired`. (The account layout also differs, in how it stores the
verification key and its version, but mina-signer does not sign accounts.)
`protocolVersions.txnVersion` is `4` in Mesa and `5` in the next format.

An account update that keeps its permissions still hashes their placeholder
value, so the delta changes the commitment of **every** zkApp command, not only
those that set permissions.

## What is vendored (3 files) and what is reused

- **`js-layout.ts`** — verbatim snapshot of `gen/v1/js-layout.ts`.
- **`transaction-json.ts`** — verbatim snapshot of `gen/v1/transaction-json.ts`,
  with its import paths repointed.
- **`transaction-bigint.ts`** — a rewired shell of `gen/v1/transaction-bigint.ts`:
  - imports the vendored `./js-layout.js` and `./transaction-json.js`,
  - re-imports the generic layout machinery and all leaf types from the
    **shared** current bindings,
  - overrides only `TransactionVersion` so `empty()` returns `txnVersion 4`.

The shared generic machinery and leaves (`from-layout.ts`, `binable.ts`,
`generic.ts`, `transaction-leaves*.ts`, `derived-leaves.ts`) are unchanged since
`bb34e65e7`:

```
git diff -w bb34e65e7 HEAD -- src/bindings/lib/ src/bindings/mina-transaction/v1/
```

The berkeley vendored layout reuses `./transaction-json.ts`, whose JSON shapes
it shares.

## Re-diff check (run if the shared bindings ever change)

If the diff above is ever non-empty beyond reordering, the reuse assumption
breaks and the affected file needs a real snapshot here. The golden vectors in
`../test-vectors/mesa.ts` are the backstop: `../mesa.unit-test.ts` will fail if
the Mesa output ever drifts.

## Learnings
- mina-signer@2.9.0 does NOT exist on npm; o1js v2.9.0 shipped mina-signer@3.0.7. 3.0.7 Network type is only 'mainnet'|'testnet'; we used 'testnet' and our 'testnet' domain matches (legacy sigs match golden).
- AccountUpdate.empty() leaves permissions unset (Option=none), so txnVersion(3vs4) only bites when permissions.setVerificationKey present (zkapp2). The fee-payer delta carrier is appState padding (8 vs 32).
- from-layout maps supplied arrays 1:1 ignoring staticLength; padding only on omitted/undefined. So cross-era guard checks array LENGTH not non-null count.
- DEVIATION from plan: cross-era guard enforces berkeley->8 ONLY. Mesa stays permissive (no length enforcement) because the existing HEAD test vector accountUpdateExample is length-8 and flows through the Mesa path (zkapp.unit-test.ts) — enforcing mesa->32 would regress it. Documented; flag for reviewer.
- Era params default to 'mesa' on all internal sign-zkapp-command fns -> backwards compatible for existing callers/tests. verifyZkappCommandSignature: era inserted before optional feePayerPublicKeyBase58; no existing caller passes that 4th arg (verified).
- Do NOT use ./run for berkeley scratch checks (needs root dist prebuilt). Use a temp tsconfig extending tsconfig.mina-signer.json including the unit test, compile, run compiled .js from src/mina-signer/dist/node.
